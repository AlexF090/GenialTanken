# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

GenialTanken shows current fuel prices of nearby gas stations as a list and on a map. Version 2 is an Angular + NestJS rebuild of an older React app. `README.md` covers setup, environment variables and deployment; `ROADMAP.md` (German) records architecture decisions and planned phases (Postgres/Prisma persistence, then auth). Hosting must stay on free tiers — ask before introducing anything paid.

## Commands

Node 26 or newer (`.nvmrc`, `engines`), pnpm 12.8.1 (pinned via `devEngines`). Run from the repository root.

```bash
pnpm install                 # also builds packages/contracts and installs the lefthook Git hooks (`prepare` scripts)
pnpm dev                     # web (http://localhost:4200) + API (http://localhost:3000) in watch mode
pnpm build                   # contracts, API, web
pnpm preview:web             # build web, serve it with the Worker via wrangler dev (needs apps/web/.dev.vars)
pnpm deploy:web              # build web, wrangler deploy to Cloudflare Workers (manual; CI normally deploys)
pnpm test                    # unit tests of all workspaces
pnpm --filter api test:e2e   # API end-to-end tests (Supertest against fake upstreams)
pnpm test:e2e                # Playwright; starts mock upstream, API and web itself
pnpm lint                    # ESLint for the whole repository
pnpm typecheck               # tsc in every workspace
pnpm format:check            # Prettier (format:write to fix)
```

Single tests:

```bash
pnpm --filter api exec vitest run src/common/map-with-concurrency.spec.ts
pnpm --filter api exec vitest run --config vitest.config.e2e.ts test/stations-search.e2e-spec.ts
pnpm --filter @genialtanken/contracts exec vitest run src/station.spec.ts
pnpm --filter web exec ng test --watch=false --include src/app/pages/settings-page/settings-page.spec.ts
pnpm --filter web test:worker             # Cloudflare Worker tests (plain Vitest)
pnpm --filter e2e exec playwright test tests/explore.spec.ts
pnpm test:scripts                         # Vitest for scripts/ (e.g. verify-wrangler-configuration)
```

CI (`.github/workflows/ci.yml`) runs format, lint, typecheck, unit, API e2e, build, Docker image build, Playwright and `pnpm audit --prod`. It skips draft pull requests (every job has a draft condition; `ready_for_review` triggers it), so open pull requests as drafts and mark them ready when final. `deploy-web.yml` (triggered by `workflow_run`, never runs code from the pull request) deploys only when the CI run produced the `web-dist` artifact (`dist/web/browser` plus `worker/` sources): `wrangler deploy` for `main`, `wrangler versions upload --preview-alias pr-<number>` for pull requests (`https://pr-<number>-genialtanken.alexf090.workers.dev`). It takes `apps/web/wrangler.jsonc` and `scripts/verify-wrangler-configuration.ts` only from the default branch; the script rejects a `build` section, so keep the file free of build commands. Every CI job repeats the draft condition through the YAML anchor `is-not-draft`; Playwright browsers come from the composite action `.github/actions/setup-playwright`. Only builds of `main` embed the Mapbox token (it is restricted to the production URL); previews use OpenStreetMap tiles.

Releases are automatic (`release.yml`, triggered by `workflow_run` after CI passed for a push to `main`): semantic-release (`release.config.js`, preset `conventionalcommits`) bumps every `package.json`, writes `CHANGELOG.md` (excluded from Prettier), commits `chore(release): <version> [skip ci]`, tags `v<version>` and creates the GitHub release. It pushes with the secret `RELEASE_TOKEN` (admin token; `main` is protected) and then deploys the API through `RENDER_DEPLOY_HOOK_URL`, because Render's `checksPass` skips the check-less release commit. Lefthook is off in that job (`LEFTHOOK: 0`); `workflow_dispatch` restarts a failed release. Pull requests are squash-merged, so the pull request title decides the version; `pull-request-title.yml` checks that it follows Conventional Commits (required status check). Never bump versions or create tags by hand.

Git hooks (`lefthook.yml`, installed by the root `prepare: lefthook install`): pre-commit runs `prettier --check` and ESLint on the staged files, pre-push runs `pnpm typecheck` and `pnpm test`. Skip them with `LEFTHOOK=0`. The hooks are installed for the Linux binary inside the dev container, so committing from the macOS host on the same checkout may fail; run `pnpm install` on the host or use `LEFTHOOK=0`.

## Architecture

pnpm workspaces with the official Angular and Nest CLIs — deliberately no Nx (see ROADMAP).

- `packages/contracts` (`@genialtanken/contracts`) — zod 4 schemas, inferred types and pure helpers shared by web and API (`Station`, `StationsQuery`, `apiErrorSchema`, `latitudeSchema`/`longitudeSchema` and `distanceInMeters` in `coordinates.ts`, `WEEKDAYS`/`emptyOpeningTimes()` in `opening-times.ts`, `MILLISECONDS_PER_*` in `units.ts`, …). The package declares `"sideEffects": false`, so modules must not have side effects at module level. Consumers import the compiled `dist/`, so **rebuild after changing it** (`pnpm --filter @genialtanken/contracts build`) before API/web see the change.
- `apps/api` — NestJS 12 backend-for-frontend, ESM. The browser never calls upstream sources directly.
- `apps/web` — Angular 22, standalone, zoneless, signals, `httpResource`, Signal Forms, Leaflet.
- `apps/web/worker` — Cloudflare Worker `genialtanken` with static assets (`apps/web/wrangler.jsonc`): it serves the Angular build as a single-page application and runs first only for `/api/*` (`run_worker_first`), which it proxies to the API in production. Entry `worker/index.ts`, proxy modules in `worker/api/`. It reads `PROXY_SHARED_SECRET` and accepts only https API origins, except `localhost`, `127.0.0.1` and `[::1]` (`worker/api/api-origin.ts`). Its `scheduled` handler (cron `*/5 * * * *` in `wrangler.jsonc`, `worker/keep-awake/`) keeps the free Render instance awake: after a random delay of up to 2 minutes, and only if the call itself falls between 06:00 and midnight `Europe/Berlin`, `GET <API_ORIGIN>/health` with a timeout (calls at most 7 minutes apart, 12 when Cloudflare skips one run, below Render's 15 idle minutes; a spec checks that against `wrangler.jsonc`); failures are logged, never thrown. The web app also calls `GET /api/wake-up` (`WakeUpController` in `apps/api/src/health/`, rate limited like every route, `204`) on start without waiting (`provideApiWakeUp` in `core/api-wake-up/`). Header names and the unavailable message are duplicated from contracts on purpose (the deploy bundles `worker/` without `node_modules`); specs keep them in sync.
- `e2e` — Playwright against real web + API with a local stand-in for the French open data API and Photon (`e2e/mock-upstream.ts`, recorded data in `e2e/data`; Photon answers keyed by normalized query in `photon-places.json`). It uses its own ports (API 3100, web 4300 with `e2e/web-proxy.conf.json`, mock upstream 4110), so a running dev server on 3000/4200 is never reused; the e2e API and the PWA server are never reused either (fresh caches and build every run). Any unmocked outgoing request fails the run; a `globalTeardown` checks the mock upstream for unexpected requests. Project `chromium` (desktop) runs every spec except `bottom-sheet.spec.ts` and `tests/pwa/`; the `mobile` project (Pixel 7) runs `bottom-sheet.spec.ts` and `accessibility.spec.ts`; the `pwa` project runs `tests/pwa/` against a production build with the service worker (`ng build --output-path dist/e2e-pwa`, served by `e2e/pwa-server.ts` on port 4400 with a proxy to the e2e API): offline start, the update notice and the broken-cache reload (`application-update.spec.ts`). `history-and-focus.spec.ts` checks that closing a sheet card or the settings never leaves a history entry Back would reopen, and that focus never falls to `body`. `entry-points.spec.ts` covers the ways into favorites and settings (sheet controls, deep links). axe scans use `wcag2aaa` too, also with more contrast and reduced transparency. `e2e/product-shots/` is not a test: `node e2e/product-shots/capture-product-shots.ts` screenshots the live production app and composes the README images in `docs/images/` (`composition.html`).

ESLint forbids `apps/web` and `apps/api` from importing each other; shared code goes into contracts.

### API request flow

1. `StationsController` validates query/params with Nest's built-in Standard Schema validation using the zod schemas from contracts (no `nestjs-zod`).
2. `StationsService` fans out to all enabled `FuelPriceProvider`s (`FUEL_PRICE_PROVIDERS` injection token) with `Promise.allSettled`. Partial results are fine; only when every provider fails does it throw `UpstreamUnavailableError` (`common/upstream-unavailable-error.ts`), which `ApiErrorFilter` answers with `502`. It computes exact distances, filters by radius and fuel, sorts and caps at 100.
3. `GET /api/stations/by-identifiers?identifiers=<comma-separated, 1–50 after removing duplicates>` (`stationLookupQuerySchema` in contracts `station-lookup.ts`) is declared before `:id`, because `by-identifiers` also matches the identifier pattern. `findStationsByIdentifiers` looks each identifier up with its provider and answers `{ stations, unavailableIdentifiers, failedIdentifiers }`; only when every lookup fails does it throw `UpstreamUnavailableError`. The web favorites use it (`StationsApi.loadStationsByIdentifiers`, chunks of 50).
4. Providers live in `src/fuel-price-providers/<country>/`: a provider class, a zod schema for the upstream payload, and a pure `to-station-from-<country>.ts` mapper (unit-tested) and its upstream paths (`france/french-upstream-paths.ts`, reused by the tests). Upstream HTTP goes through `UpstreamFetcher` (see below); `parseFrenchRecords` drops invalid records one by one. Providers return `distanceInMeters: null`; the service fills it in. The French provider keeps every record of a search answer by identifier in `FrenchSearchedRecords` (`france/french-searched-records.ts`), its own bounded LRU apart from the shared cache (`FRANCE_SEARCHED_RECORDS_MAXIMUM_ENTRIES`, default 2000), so a detail or favorites lookup of a recently listed station needs no upstream request. A record lives at most `CACHE_TIME_TO_LIVE_IN_SECONDS` after its upstream fetch (`UpstreamFetcher.fetchJsonAnswer` reports the fetch time also for cached answers), and an older answer never replaces a newer record; only other stations are queried by `id=` (the open data portal often needs seconds for that). Station IDs are country-prefixed (`fr-…`, see `station-identifier.ts`) so detail lookups route to the right provider; a prefix without provider (e.g. old `de-…` favorites) is answered as unknown.
5. French open data has no station names or brands. `FrenchStationIdentityLookup` (`france/french-station-identity-lookup.ts`) takes them from the price service's station pages (`FRANCE_STATION_DETAILS_BASE_URL` + `/map/recuperer_infos_pdv/<id>`, HTML parsed by the pure `parse-french-station-identity.ts`) through `UpstreamFetcher.fetchText`, at most `MAXIMUM_PARALLEL_UPSTREAM_REQUESTS` (8, `upstream/maximum-parallel-upstream-requests.ts`) at once (`mapWithConcurrency`), cached a week. One search waits for its pages at most `FRANCE_STATION_DETAILS_TIME_BUDGET_IN_MILLISECONDS` in total (default 3000, one abort signal per search). Missing or failed pages are cached as missing for 10 minutes; pages cut off by the budget are not. A missing page only leaves the name missing; the web app then titles the station by its street.
6. France is the only country for now and always enabled (registered in `fuel-price-providers.module.ts`; decision in ROADMAP). The API accepts radii up to 30 km (`MAXIMUM_RADIUS_IN_KILOMETERS` in contracts). A new country = new provider + register it there + add its code to `COUNTRY_CODES` in contracts.
7. Place search (`src/places/`): `GET /api/places` validates with `placesQuerySchema`; `PlacesService` asks Photon (komoot, `PHOTON_BASE_URL`) through `PhotonClient` (`places/photon/photon-client.ts`) with the normalized query (trim, collapse whitespace, lowercase), twice the limit and a metropolitan France bounding box (including Corsica), maps features with the pure `photon/to-place-from-photon.ts` (drops other countries), dedupes by id and cuts to the limit. Answers are cached `PLACES_CACHE_TIME_TO_LIVE_IN_SECONDS` (default one day); upstream failures become `UpstreamUnavailableError(ERROR_MESSAGES.placeSearchUnavailable)`, answered with `502`.

Cross-cutting API pieces:

- Environment is validated once at startup by `parseEnvironment()` (zod schema in `src/configuration/environment.ts`, no `@nestjs/config`) and exposed via the injectable `ApplicationConfiguration`, which exposes every duration in milliseconds (environment variables carry their unit in the name, `_IN_SECONDS` or `_IN_MILLISECONDS`); invalid values abort startup. `AppModule.forRoot(variables = process.env)` takes the variables, so tests pass them instead of patching `process.env`; the shared e2e setup is `useTestApplication()`/`useFakeUpstream()` in `test/support/`. Every upstream base URL defaults to a closed local port there, and a fake upstream fails the test on a request for a path without programmed response (program a 404 explicitly). `APPLICATION_VERSION` is provided once by `ConfigurationModule`. The API does not read `.env` files.
- `src/upstream/` (`UpstreamModule`) provides `UpstreamFetcher` for every external data source (`fetchJson`: 404 is a failure; `fetchJsonAnswer`: the same as `{ body, fetchedAt }`, `fetchedAt` being the time of the real upstream fetch; `fetchText`: 404 yields `undefined`): timeout, zod validation, cache keyed by `toCacheKey(namespace, key)` (`common/cache-key.ts`, optional per-request `cacheTimeToLiveInMilliseconds`), optional abort `signal` from the caller, failures thrown as `UpstreamError` (a caller abort becomes `UpstreamAbortedError`, deliberately no subclass of `UpstreamError`: it says nothing about the source and must not be cached as a failure). The JSON cache holds parsed answers keyed by URL, so one URL must always be fetched with the same schema. Callers turn `UpstreamError` into `UpstreamUnavailableError`.
- The cache is a bounded in-memory LRU (`@cacheable/memory`, `CACHE_MAXIMUM_ENTRIES`, default 5000), set up in `app.module.ts`.
- All client-facing error messages live in `src/common/error-messages.ts`; `api-error.filter.ts` shapes every error body to `apiErrorSchema` and logs through `describeError()`. Swagger error responses come from `ApiStandardErrors(…)` (`openapi/api-standard-errors.decorator.ts`).
- `configure-application.ts` holds HTTP setup (prefix `api`, `/health` excluded, CORS, Swagger at `/api/docs`) and is shared by `main.ts` and the e2e tests (`test/support/create-test-application.ts`), so keep setup there, not in `main.ts`.
- Rate limiting: `ClientAddressThrottlerGuard` trusts the forwarded client address only when the request carries the shared secret (`PROXY_SHARED_SECRET`) set by the Worker (`resolve-client-address.ts`); `trust proxy` is limited to one hop on purpose. The limit counts per route and client (the throttler's default key), so the wake-up call, typing in the place search and favorites lookups never use up the budget of the station search. Header names and the unavailable message are shared in contracts (`proxy.ts`).
- Nest DI needs runtime class references, so `consistent-type-imports` is off for `apps/api`. Relative imports in the API use the `.js` extension (ESM).

### Web structure

- `src/app/core/` — framework-light state and services: signal stores (`NearbyStationsStore`, `SettingsStore`, `FavoritesStore`), `StationsApi` (validates every response with the contracts schemas through `parseResponse` in `core/http/`, which throws `UnexpectedResponseError` on contract violations), geolocation, browser storage. Log through the injectable `Logger` (`core/logging/logger.ts`), never `console`; only the bootstrap in `main.ts` uses `console.error`.
- `src/app/pages/` — routed container components that inject stores.
- `src/app/ui/` — presentational components (inputs/outputs only). `BrowserEdgeTint` (`ui/browser-edge-tint/`) draws two opaque 16 px strips (`--color-chrome-opaque` top, `--color-surface` bottom) at the window edges, because Safari 26+ tints the bars behind the clock and the floating toolbar from fixed edge elements and ignores `theme-color`; it shows only in the Safari tab (`pointer: coarse`, not `display-mode: standalone`, not forced colors), since the installed app keeps the system blur. Reusable controls: `SelectMenu` (iOS-style pull-down menu for single-choice options; top layer via Popover API where available, its own dismissal logic so it behaves the same in jsdom) `PlaceSearchField` (ARIA 1.2 combobox; the host renders its suggestions through `suggestionsTemplate`, `isCancelable` adds „Abbrechen“), `FilterChip` (capsule trigger of a `SelectMenu`; a 36 px capsule `--layout-chip-height` drawn as `::before`, the button keeps the 44 px target through `--layout-chip-overhang`) and `SheetDialog` (native `<dialog>` with `showModal()`: focus trap, Escape, inert background; page sheet on phones, centered card from 48rem; `sheetDialogFooter` slot).
- No tab bar (decision in ROADMAP): the map is the app and every page is a child route of the explore page, like Apple Maps. The map fills the window under the system bars (`viewport-fit=cover`; the status bar keeps only the system's own glass blur, no scrim of ours); the body never scrolls there. On phones a draggable sheet (`BottomSheet`, measured detents `peek`/`half`/`full`; `half` is 55 % of the window height without the iOS gap below the window, so two to three list rows show, at least 136 px above `peek` (otherwise `half` falls together with `full`)) holds everything, from 48rem a floating side panel with the same content. Sheet header: the place search (`injectPlaceSearch()` from `pages/explore-page/place-search.ts` through `PlacesApi`, debounced with Angular's `debounced()`; focusing it starts the search mode (`injectSearchMode()` in `search-mode.ts`): sheet at `full`, suggestions in the sheet instead of a popover so the keyboard never covers them and stay on blur like in Apple Maps, only „Abbrechen“, Escape or choosing a place (sets `half`) end it; on touch devices the focus then moves to the result summary so the keyboard closes, elsewhere it stays in the field), the round settings link, the filter chips Kraftstoff, Radius and Sortierung, the one-line result summary (`ResultSummaryLine`: visible „4 Tankstellen · 5 km“ with non-breaking spaces, the full sentence with place and radius as visually hidden `role="status"` and focus target, „Aktualisieren“ as icon button; the app's only loading indicator: the icon turns while stations load (static under reduced motion), the button is then `aria-disabled` and ignores presses, „Tankstellen werden geladen …“ is announced only after 700 ms, and after 4 s the cold-start hint replaces the short line on one line, in full in the status) and the offline notice. Below: the favorites row (`FavoritesRow` over `FavoriteStationsResource`, which loads favorites in chunks of 50 for row and page alike), the station list (skeleton rows on the first load, a reload keeps the shown stations) and, after its third station, the installation hint (`StationList` slot `stationListInsertion` with `insertionAfterRow`: two lists „Tankstellen“ and „Weitere Tankstellen“ whose rows keep `aria-posinset`/`aria-setsize` over all stations, one shared row `ng-template`; with three stations or fewer after the list; `InstallationHintBanner` over `core/installation/installation-hint.ts`: one line with „Installieren“ for `beforeinstallprompt` or „So geht’s“ expanding the iOS steps, dismissed once for good; closing focuses the data source link). Dismissing a notice or the installation hint moves the focus on when it would fall to `body` (`recoverFocusWhenChanged` in `focus-recovery.ts`). On the map stay the locate button, on phones the compact zoom buttons below it (`ZoomControls` in `ui/zoom-controls/`, „Hineinzoomen“/„Herauszoomen“, `aria-disabled` at the zoom limits; from 48rem Leaflet's own), and „In diesem Bereich suchen“ once the user drags the map away from the search center (`StationsMap.visibleCenterChanged` → `shouldOfferAreaSearch` → `SearchCenterStore.useMapArea`, source `map-area`); they hide while a full sheet covers them.
- Sheet cards: `stations/:id` and `favorites` render in the sheet (or panel) instead of the list (`SheetCard` in `pages/explore-page/sheet-follows-card.ts`, which also sets the detent); the list stays mounted but hidden. `settings` opens `SettingsPage` in a `SheetDialog` over the map; closing returns to `/` and the browser returns the focus. Closing settings, a card or favorites goes through `injectCloseToExplore()` (`core/navigation/close-to-explore.ts`; `explore-routes.ts` keeps only the paths and URL matching the first paint needs, so lazy pages' helpers stay out of the initial bundle): history back when the app itself navigated there from the explore page, otherwise (deep link, after Back/Forward) `/` with `replaceUrl`, so Back never reopens what was closed. Paths in `core/navigation/explore-routes.ts`; deep links and manifest shortcuts open over the map.
- Map geometry: a chosen price tag is always centered in the part of the map not covered by overlays (`centerForVisibleArea` in `ui/map/map-viewport.ts`; the explore page measures map controls, sheet and panel with `observeElementBounds` and turns them into insets with `mapViewportPaddingFor` in `map-viewport-padding.ts`), also while the sheet moves. `core/layout/visual-viewport.ts` writes the on-screen keyboard height to `--layout-keyboard-inset` (iOS ignores `interactive-widget=resizes-content`). `core/layout/viewport-gap.ts` works around an iOS 26 bug of installed apps, whose layout viewport ends short of the screen: only with `navigator.standalone`, it writes `screen.height − innerHeight` (1–120 px, measured while no keyboard is open) to `--layout-viewport-gap-bottom`, which extends the explore page, the sheet, the phone sheet dialog and the update notice to the real bottom edge; `styles.scss` already brings the window to full height in `display-mode: standalone` (`html` `min-height: min(100lvh, calc(100% + env(safe-area-inset-top)))`, `body` `min-height: 100%`; `min()` keeps the page from scrolling, WebKit bug 316008), so the measurement then yields 0 and stays as a safeguard; `html` carries the opaque sheet color and `body` no background, so any gap left looks like the sheet.
- List rows (`StationList`): price tile first (`PriceTile`, `ui/price-tile/`), tinted by `priceLevelOf` (thirds of the shown price range, the cheapest solid green, like the price tags), title, „distance · address“, star and ⓘ. With `selectsOnMap` the title button selects the station on the map and the ⓘ link, the only link of the row, opens the card; elsewhere the title links to the card. The station card (`StationDetailPage` with `StationDetail`) opens at `half` with equal-width action tiles Route, Favorit and Teilen, then prices, opening times and address. A station already known from the results, the favorites or the opened station (`KnownStations` in `core/stations/known-stations.ts`, sources with their load time through `KNOWN_STATION_SOURCES`, recorded by `injectLoadedAt` in `core/time/loaded-at.ts`; favorites that keep old prices after a failed lookup keep their older load time) renders at once without a request; data older than 5 minutes is refreshed in the background, and a failed refresh keeps it; only unknown stations (deep links) load, shown as a skeleton shaped like the card (title and subtitle, two or three action tiles depending on `SHARE`, „Preise“ and `SkeletonRows variant="price"`) with the cold-start hint after 4 s, and „Erneut versuchen“ on failure. The card and the favorites page render their `role="status"` empty and fill it after the first render, so screen readers announce the loading; the favorites row (tile skeletons up to the number of favorites) loads silently. Only the card offers a route (`RouteButton`: a native `<select>` over the tile, so phones show their system picker; universal links of Apple Karten, Google Maps and Waze from `core/navigation-apps/`, opened via `OPEN_EXTERNAL_URL`). Teilen uses the `SHARE` token (`core/sharing/share.ts`, `navigator.share`) and is not rendered without it. The card's station is selected on the map (`ExplorePage.openedStationIdentifier` from the URL; `OpenedStationStore` shares the loaded station so a station outside the results moves the search there, source `station`). ✕ (`CloseButton`, `ui/close-button/`, the round ✕ of cards, dialogs and hints) or Escape close it; the list then has the station selected and focused (through `BottomSheet.scrollPosition`/`restoreScrollPosition` and `StationList.focusStation`, not DOM queries). Favorites link to the same card.
- Service worker (`@angular/service-worker`, production configuration only, `registerWhenStable:30000`): `ngsw-config.json` caches the app shell and assets but has no `dataGroups`, so prices never come from a cache (decision in ROADMAP); the `bypassServiceWorkerForApi` interceptor (`core/http/bypass-service-worker.ts`) adds `ngsw-bypass` to `/api` requests, so offline failures keep status 0. `public/_headers` sets `Cache-Control: no-cache` for every path (`/*`; rules match the requested path, not the SPA fallback `index.html`, so this also covers app routes, unknown paths and trailing slashes), and each cacheable rule (hashed `*.js`/`*.css` immutable, media, icons, manifest) removes the inherited header first (`! Cache-Control`); the service worker files, `ngsw.json` and `index.html` keep explicit `no-cache` rules; `scripts/static-asset-caching.spec.ts` checks that. `ApplicationUpdateStore` (`core/application-update/`) checks for a new version when the page becomes visible again and offers „Neu laden“ through `UpdateNotice` in the shell, never on a timer (it reloads after 3 seconds even if activation hangs); a broken cache (`unrecoverable`) reloads on its own at most once every 10 minutes (time stamp in `SESSION_STORAGE`; blocked storage counts as just reloaded), then the notice asks „Die App muss neu geladen werden.“; while the settings dialog is open its footer shows the notice, because the modal makes the shell inert; `UpdateNotice` renders its live region empty and fills it 100 ms later, so screen readers announce a notice that is already pending. `NetworkStatus` (`core/network/network-status.ts`) drives the offline notices, and `reloadWhenReconnected` reloads stations, favorites and the card a second after the connection returns, with one retry 4 seconds later (`online` often fires before the network works). `FavoriteStationsResource` keeps the shown stations when a reload fails and reports the failure alongside; a refresh asks only for the currently starred stations.
- Shared building blocks; reuse them instead of rebuilding: loading placeholders (global `.skeleton-block` in `styles/skeleton.scss`: appears after 300 ms so fast answers never flash, pulses between `--color-skeleton` and `--color-skeleton-pulse`, still under reduced motion, outlined under more contrast and forced colors; `SkeletonRows` with the variants `station`, `text`, `price` and `tile`, shaped like the real rows with the same container queries), timers (`injectHasLastedFor` in `core/time/has-lasted-for.ts`, `injectShowsColdStartHint` in `core/api-wake-up/cold-start-hint.ts`), formatting (`formatKilometers`/`KilometersPipe`, `pluralize`), labels (`core/stations/price-labels.ts`, `core/http/request-failure-messages.ts`, `core/application-name.ts`), `HTTP_STATUS` (`core/http/http-status.ts`), `uniqueIdentifier` (`core/dom/`), `observeElementResize`/`observeElementBounds` (`core/layout/`), `injectPrefersReducedMotion`, `LabeledOption`/`fuelTypeOptions`, `resourceValueOr`, `stationRoute`/`injectOpenedStationIdentifier` (`core/navigation/station-route.ts`), the clock `CURRENT_DATE` (`core/time/`), `ExternalLink` (`ui/external-link`). Leaflet is imported only through `ui/map/leaflet.ts`; tiles, price tag icons and teardown live next to it, the markers in `StationMarkerLayer`. SCSS mixins `focus-ring` and `floating-material` (`src/styles/`) replace copied focus and material rules; global classes in `styles.scss` replace copied controls: `.icon-button` (`--circled` with `__circle` for the grey round ✕ and settings buttons, `--row-action`), `.action-tile` (`--primary`), `.text-button`, `.toast`, `.message`.
- Favorites persist through the abstract `FavoritesRepository` (localStorage implementation today; ROADMAP phase 2 swaps in an API-backed one).
- The app always calls same-origin `/api` (dev: `proxy.conf.json`; production: Worker), so no API URL is baked into the build.
- Styling uses design tokens in `src/styles/tokens.scss`, modeled on Apple's Human Interface Guidelines (system font, iOS system colors, translucent materials). The target is WCAG 2.2 AAA (decision in ROADMAP): every text token pair keeps at least 7:1 and non-text 3:1 in light and dark, and every new or changed pair records its ratios in the comment next to it. Materials turn opaque with a hairline (`opaque-materials`) on `prefers-reduced-transparency`, `prefers-contrast: more` and without `backdrop-filter`, and use system colors under `forced-colors`. The focus ring has two tones (tinted outline between halos in `--color-focus-ring-halo`). Font size tokens are named after the iOS text styles (`--font-size-body`, `--font-size-title-2`, …) in `rem`, and iOS scales them with Dynamic Type (`font: -apple-system-body` in `styles.scss`); body text has line height 1.5 and prose at most 80 characters. Targets are at least `--layout-touch-target` (44 px). The brand accent is indigo, the only hue the map leaves free (green, orange and red are price levels, blue is the own position): `--color-brand` is #3a37b8 in light and #cdccff in dark (gradient stops `--color-brand-gradient-*` #5e5ce6 → #3a37b8, the drop of the icon); filled controls (`--color-action`) are dark indigo with white text in light and light indigo with dark text in dark; links and the focus ring (`--color-action-text`) are #3330a8 in light (keeps 7:1 on the grey fills and the menu highlight) and the light indigo in dark; icons (`--color-tint-vivid`) the brand indigo. The cheapest price (`--color-highlight`) stays green, the own position Apple blue. `scripts/brand-contrast.spec.ts` checks the core brand pairs in light and dark. Depth is tokenized too: plastic price fills (`--gradient-price-*` with `--color-price-*-top/-bottom`, the bottom also fills the tag's pointer), `--shadow-price-tag(-raised|-selected)`, controls (`--gradient-action*`, `--gradient-control-sheen`, `--shadow-control`, `--shadow-control-pressed` via the `pressed-control` mixin in `styles.scss`), glass (`--shadow-sheet`, `--shadow-panel`, `--color-material-highlight`); under `prefers-contrast: more` and forced colors the gradients and gloss drop to flat fills with a drawn edge. A selected price tag keeps its price-level fill and gets a ring (`--color-selection-ring` around a gap in the surface color, `--color-selection-ring-gap`), so the selection never makes a price look cheap. Keep the `theme-color` metas in `index.html` in sync with `--color-chrome`; the manifest's `theme_color`/`background_color` are the icon's indigo `#3A37B8`, so the launch screen matches the icon. `e2e/product-shots/composition.html` copies a few light values.
- Brand assets: sources in `apps/web/icon-source/` (`app-icon.svg` full-bleed master, also the apple-touch icon; `app-icon-rounded.svg` for manifest icons of purpose `any`; `app-icon-maskable.svg` with the motif inside the safe circle; shortcut icons; `wordmark.svg`). `apps/web/public/favicon.svg` is a simplified icon for tab sizes. `pnpm generate:app-icons` (`scripts/generate-app-icons.ts`, renders with Playwright's Chromium) writes `public/icons/*.png` and `favicon.ico`; rerun it after changing a source. The wordmark is the inline SVG component `ui/wordmark/` ("Genial" in `currentColor`, "Tanken" and the drop in `--color-wordmark-accent`, one `role="img"` named after the app); it heads the side panel from 48rem and signs the settings dialog.
- Component selectors use the `app` prefix; templates are linted with angular-eslint accessibility rules. Shared test helpers are in `src/testing/`: fake geolocation/storage (`storedSettings`/`storedFavorites`), station fixtures (`withPrices`, `withDistance`), `render-page.ts` (`renderWithInputs`, `hostElementOf`, `getRadio`), `FakeResizeObserver` (reset after every test by `global-test-setup.ts`, registered in `angular.json` `setupFiles`; specs share one module graph), `FakeKeyboardAwareWindow`, `FakeServiceWorkerUpdate`, a `<dialog>` polyfill for jsdom (installed by the setup file; like browsers it fires `close` in a later task, honors `autofocus` and closes the top modal dialog on Escape anywhere, so specs wait for the `close` event; real focus return is checked in Playwright), `api-urls.ts`. Playwright helpers (`pageHeading`, `expectColorScheme`, `seedFavorites`, `sheetHandle`, `settingsDialog`, `favoritesRow`/`favoritesList`, `suggestHomeScreenSteps`, and `serviceWorkerTest` for the `pwa` project) are in `e2e/fixtures.ts`, linted by `eslint-plugin-playwright`.
- `NG_APP_MAPBOX_ACCESS_TOKEN` is injected at build time via `--define`; without it the map falls back to OpenStreetMap tiles (which e2e relies on).

## Conventions

- TypeScript strict everywhere; `interface` for object shapes (lint-enforced), `import type` for type-only imports (except in the API, see above).
- Identifiers and comments use full words, no abbreviations (`configuration`, `identifier`, `InMilliseconds`).
- Prettier: single quotes, `printWidth` 100, `arrowParens: avoid`, `trailingComma: es5`.
- Dependencies are pinned exactly (`saveExact`), and `minimumReleaseAge` blocks releases younger than one day. Security fixes for transitive dependencies go into `overrides` in `pnpm-workspace.yaml`, keyed by the vulnerable range and commented with the advisory; overrides do not reach auto-installed peers (refresh those with `pnpm update -r <package>`). The API's Node.js runtime in production is the base image in `apps/api/Dockerfile` (exact tag plus digest, both stages together; Dependabot checks it daily), not `.nvmrc`, which names only the major version for CI and local tooling.
- Commits and pushes run the lefthook hooks (see Commands); `LEFTHOOK=0` skips them.
- Deployment and release steps: `docs/deployment.md`.
